# Подключение облачной инфраструктуры

Локальная заготовка готова к подключению. Эти шаги создают реальные внешние ресурсы и выполняются после выбора аккаунтов. Пароли и служебные токены не отправляйте в чат и не коммитьте.

## 1. GitHub

Репозиторий уже создан: [MaxFolmer/china_replicas](https://github.com/MaxFolmer/china_replicas). Он публичный. Клонирование для второго разработчика:

```sh
git clone https://github.com/MaxFolmer/china_replicas.git
cd china_replicas
npm ci
npm run dev
```

Пригласите друга через Settings → Collaborators. После первого успешного CI настройте защиту main с обязательной проверкой `check` и работой через pull request. Если приватный тариф не поддерживает защиту веток, договоритесь о PR в команде.

## 2. Supabase

Проект уже создан: [wxdpvxygeyieyurdqbup](https://supabase.com/dashboard/project/wxdpvxygeyieyurdqbup).
API URL: `https://wxdpvxygeyieyurdqbup.supabase.co`.

Не включайте private в exposed schemas. Для начала достаточно одного проекта разработки; production стоит выделить перед запуском.

```sh
npx supabase login
npm run db:link
npm run db:push:preview
npm run db:push
```

Первая миграция уже применена и зарегистрирована; `db push` нужен для следующих миграций. `db push` применяет миграции к выбранному облачному проекту. Перед подтверждением проверьте project-ref. `seed.sql` предназначен для локального запуска: первые категории уже добавлены через SQL Editor из этого файла. Секреты не задавайте в аргументах команд.

Скопируйте Project URL и publishable key из Dashboard в `.env.local`. Настройте Auth Site URL/Redirect URLs под локальный адрес и будущий домен. Публичная регистрация не даёт прав редактора.

Создайте пользователей редакторов через Supabase Dashboard/Auth. В SQL Editor назначьте права по действительному UUID:

```sql
insert into private.admins (user_id) values ('UUID_ИЗ_AUTH_USERS');
```

Этот запрос может выполнять владелец БД. Не выдавайте браузеру доступ к private.admins.

## 3. Проверка подключения

1. В браузере с публичным ключом убедитесь, что черновики, import_items и verification_logs недоступны.
2. Проверьте, что редактор может создать черновик, а обычный пользователь не может его читать/менять.
3. Добавьте настоящий проверенный объект; при публикации должны быть координаты WGS84, подтверждение существования и дата проверки.
4. Проверьте, что маркер появился и сторонний пользователь не может редактировать данные.
5. Для входа редакторов пока используйте Dashboard; интерфейс авторизации ещё не реализован.

## 4. Хостинг

Проект собирается как статическое приложение: `npm ci`, `npm run build`, папка `dist`. Можно подключить GitHub-репозиторий к Vercel или другому статическому хостингу. Укажите переменные VITE_SUPABASE_URL и VITE_SUPABASE_PUBLISHABLE_KEY в настройках окружения до сборки. Служебные ключи для публикации frontend не требуются.

Перед публичным запуском выберите поставщика тайлов и проверьте атрибуцию. При появлении маршрутов React Router добавьте SPA fallback на index.html в выбранном хостинге.

Автоматическое применение удалённых миграций намеренно не включено: сначала нужен выделенный production-проект и порядок выпуска миграций.
