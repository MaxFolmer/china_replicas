# Архитектура первой версии

Браузер → React/Leaflet → Supabase Data API → PostgreSQL с RLS.

Картографическая подложка и каталог независимы. Источник тайлов задаётся через VITE_MAP_TILE_URL/VITE_MAP_ATTRIBUTION. По умолчанию используются OSM-тайлы только для разработки; перед публичным релизом выберите поставщика с подходящими условиями и сохраните атрибуцию. OSM не является доказательством существования объекта.

## Данные

- attractions: карточка копии, оригинал, координаты WGS84, существование, доступность и публикация.
- provinces → cities → attractions, categories → attractions: география и классификация.
- sources: ссылки на источники и исходные координаты WGS84/GCJ02/BD09/unknown.
- attraction_images: ссылки, тип replica/original, источник, лицензия и атрибуция. Файлы хранятся в публичном bucket `attraction-images`; загружать и удалять их могут только редакторы.
- verification_logs: история проверок, доказательства и редакционные заметки. Доступна редакторам.
- import_batches → import_items: исходный JSON и решение редактора. Приватны.
- favorites: избранное владельца; UI появится позднее.
- private.admins: редакторы, назначаемые владельцем базы через SQL.

Черновик допускает отсутствие координат. Публикация требует пары координат, existence_status=exists и last_verified_at. Это минимальные технические условия, а не автоматическое доказательство актуальности. Редактор заполняет источники и запись проверки, затем публикует. Админка сохраняет объект, источники, фотографии, журнал и last_verified_at через транзакционную функцию admin_save_attraction.

Импорт сохраняет raw_data без преобразования, далее нормализация, поиск дубликатов, проверка источников и создание черновика. Автоконверсия координат и массовая публикация сейчас не выполняются.

## Доступ

Посетители и обычные пользователи читают опубликованные объекты, их источники/изображения и справочники. Обычный пользователь может добавлять и удалять только собственное избранное. Редактор управляет каталогом, импортом и проверками. JWT user_metadata не даёт прав редактора.

Веб-клиент использует публичный ключ; RLS применяется в базе. Service-role ключ в frontend не нужен. private не включается в API exposed schemas.

2. Вход редакторов, админка и атомарное сохранение с проверкой/публикацией реализованы.
3. Изучить реальные образцы архива и написать импортёр с предпросмотром.
4. Поиск и фильтры реализованы на клиенте; добавить пагинацию по области карты (сейчас максимум 1000 объектов).
5. Настроить Storage и права загрузки, карточки оригинал/копия.
6. Выбрать тайлы, подключить домен и хостинг; проверить поведение на телефоне.

Отдельный сервер и PostGIS для первого каталога не требуются. Их добавление стоит обосновывать фоновыми задачами или пространственными запросами.
